### 핵심 결론

- 아키텍처는 TruthGraph → KnowledgeState → GameRule → Dialogue/AI → PixiJS Presentation의 5계층으로 분리된다.
- AI는 판정자가 아니라 판정 이후 표현자다. 허용 Claim과 reaction key만 받아 대사를 생성하며 실패 시 캐시/사전 작성 폴백으로 복귀한다.
- 이번 검증에서 lint, 계층 검사, typecheck, 917개 gate test, 24개 JSON 검증, 55개 PNG 팔레트 검사, 24개 smoke test, production build가 모두 PASS했다.
- 런타임 에셋은 PNG 55개이며, 별도 `NHN AI_/` 소스 뱅크의 PNG 262개/PSD 37개/PUR 1개는 자동 로드되지 않는다. 표의 [R]/[S]/[G]가 이 차이를 표시한다.
- 생성 프롬프트 82개는 Midjourney v6 `--ar`를 보존하고, FLUX.1에서는 동일 비율의 캔버스를 별도 지정하도록 작성했다.

## SECTION 1. AI 활용 기술 & 파이프라인 내역

### 1.1 활용 AI 모델 & 개발 엔진

| 구성 | 프로토콜상 역할 | 입력/출력 계약 | 증거 등급 |
|---|---|---|---|

| Antigravity Agent Engine | 코드 베이스 리팩터링, 게이트 자동화 | 저장소 변경 요청 → 작은 패치 + 검증 결과 | E3 |
| OpenAI GPT-4o | 보조 분석, 멀티모달 검토, 대안 생성 | 코드/이미지/로그 → 리뷰 제안 | E3 |

> 모델명과 외부 도구의 실제 호출 이력은 저장소만으로 독립 검증할 수 없다. 본 문서는 첨부 프로토콜의 역할 선언(E3)과 로컬 구현 근거(E1)를 분리한다.

### 1.2 5계층 안전 아키텍처

1. **TruthGraph**: 사건의 실제 진실. 런타임 읽기 전용.
2. **KnowledgeState**: 플레이어가 확보한 지식. 진실과 분리.
3. **GameRule Engine**: 카드, 자원, 판정, modifier, 승패. 결정론적 순수 함수 중심.
4. **DialogueRenderer / AI**: 엔진이 제공한 allow-list 범위에서 표현만 생성.
5. **PixiJS Presentation**: 명시적으로 조립된 PublicDTO만 렌더링.

의존성은 아래 방향으로만 흐른다. `dependency-cruiser`, ESLint, Vitest 아키텍처 테스트가 역참조, 콘텐츠 ID 하드코딩, 엔진의 DOM/비결정 API 사용을 차단한다.

### 1.3 MCP 파이프라인 매핑

| 단계 | MCP/도구 역할 | 저장소 앵커 | 산출 증거 |
|---|---|---|---|
| Context Discovery | 프레임워크와 Zod/JSON Schema 탐색 | `src/content-io/schemas/`, `schemas/` | 스키마와 타입의 단일 원본 확인 |
| Code Audit | 계층/금지 API/ID 리터럴 감사 | `dependency-cruiser.config.cjs`, `tests/arch/` | 222 modules, 576 dependencies, violation 0 |
| Trace & Logs | 판정 로그와 AI 생성 로그 분리 | `src/engine/log/`, `src/ai/GenerationLog.ts` | 판정/표현의 감사 경계 |
| Custom Tooling | 콘텐츠, 팔레트, 시뮬레이터, 워크벤치 저장 | `tools/validate/`, `tools/palette-check/`, `tools/simulate/`, `tools/workbench-save/` | 재현 가능한 명령형 게이트 |

외부 MCP 서버의 설치 목록이나 세션 transcript는 저장소에 없다. 따라서 여기서는 MCP가 수행해야 할 기능과 로컬 도구 앵커를 매핑하며, 외부 호출 자체를 E1 사실로 주장하지 않는다.

### 1.4 Hook 시스템 - Safety & Gate Enforcement

| Hook/Gate | 실패 시 차단 대상 | 2026-08-08 실행 결과 |
|---|---|---|
| `typecheck` | 타입 불일치 및 브라우저/Node 계약 위반 | PASS |
| `test:gates` | 판정, AI 계약, 누설, UI, 아키텍처 회귀 | PASS: 107 files / 917 tests |
| `content:validate` | Zod, 참조, 도달성, 누설 규칙 위반 | PASS: 24 JSON files |
| `palette:check` | 보이는 RGBA가 16색을 초과한 PNG | PASS: 55 PNG files |
| `simulate:smoke` | BEST/flags/replay 경로 회귀 | PASS: 4 files / 24 tests |
| `build` | production bundle 및 정적 에셋 복사 실패 | PASS: 1,018 modules transformed |

저장소에는 활성 pre-commit 또는 Stop Hook이 없다. 위 항목은 package scripts 기반 품질 게이트이며, Stop Hook은 필수 게이트가 PASS하기 전 완료 선언을 막는 프로토콜상 운영 원칙(E3)이다. 이번 보고서는 동일한 의미의 수동 완료 기준을 적용했다.

### 1.5 Skill 커스텀 지식 체계

| Skill | 핵심 지식 | 강제 지점 |
|---|---|---|
| 5계층 아키텍처 준수 | Truth/Knowledge/Rule/AI/Presentation 경계 | dep-cruiser + arch tests |
| Zod 스키마 검증 | 타입/JSON Schema/의미 검증의 단일 원본 | `src/content-io/schemas/`, `content:validate` |
| PixiJS 1280x800 HD 스케일링 | 내부 640x400, 최대 2배 정수 확대, 레터박스 | `src/ui/core/integerScale.ts` |
| 15노드 무인 자동 플레이 | 15개 정본 노드, 9개 조우, 6개 이벤트, true ending | `content/common/run-strip.json`, `tests/browser/br04-turbo-run.spec.ts` |

`.agents/skills/` 또는 설치된 skill manifest는 저장소에 없다. 위 표는 코드와 테스트에 구현된 재사용 지식 계약을 프로토콜의 Skill 역할에 대응시킨 것이다.

### 1.6 Subagent 분업 자율 아키텍처

- **Browser Subagent 설계 역할**: 1440x900 Playwright viewport 안의 1280x800 게임 캔버스, 카드 호버 확장, autoplay, 스크린샷/telemetry 수집을 담당한다. 현재 실브라우저 완주 증적은 turbo 모드이며 video 모드는 DEV 계약만 존재한다.
- **Task Management Subagent**: Vite 개발 서버 생명주기와 Vitest/콘텐츠/팔레트/빌드 게이트를 비동기 관리하고 결과를 한 개의 증거 패킷으로 취합한다.
- **Lead Agent**: 요구사항, 코드 근거, 에셋 현황을 병합하고 E1/E2/E3 경계를 검토한 뒤 납품물을 승인한다.
- 저장소에는 subagent manifest나 실행 transcript가 없으므로 위 내용은 역할 기반 자동화 청사진이며, 실제 subagent 사용 이력으로 단정하지 않는다.

## SECTION 2. 전수 에셋 리스트업 및 AI 생성 프롬프트

### 2.1 공통 아트 디렉션과 상태 범례

- **[R] Runtime**: `dungeon-dossier/assets/`에서 자동 로드되는 직접 또는 범주 대응 에셋.
- **[S] Source Bank**: `NHN AI_/`에 있는 PSD/PNG 원본 또는 가까운 후보. 현재 런타임 자동 로드 대상은 아님.
- **[G] Generation Spec**: 현재 직접 대응 파일이 없어 본 프롬프트로 신규 생성할 대상.
- 공통 납품 규칙: 640x400 논리 해상도, 1280x800 2배 출력, nearest-neighbor, 안티앨리어싱/그라데이션 금지, 씬당 보이는 색 16색 이하, 텍스트/로고는 후처리.
- Midjourney 플래그는 그대로 복사한다. FLUX.1에서는 `--ar` 이후 플래그를 제거하고 UI에서 같은 비율의 canvas를 지정한다.

## SECTION 3. 실행 및 납품 프로토콜

### 3.1 이미지 제작 파이프라인

1. **Prompt freeze**: 본 표의 subject, 비율, 금지 조건을 버전 고정한다.
2. **Concept batch**: 동일 seed군으로 4안씩 생성하고 구도/실루엣을 먼저 선정한다.
3. **Geometry normalize**: 목표 비율과 안전영역에 맞춰 확장/크롭하고 내부 기준 640x400 또는 파생 규격으로 축소한다.
4. **Palette lock**: 씬 팔레트 16색으로 양자화하고 중간톤은 1-bit dithering으로 정리한다.
5. **Human retouch**: 손/얼굴/소품 겹침, 픽셀 군집, 투명 경계, 텍스트 오염을 수정한다.
6. **Runtime package**: `카테고리_이름_상태.png` 명명, 파츠 JSON/9-slice 규칙 적용, `assets/`로 승격한다.
7. **Gate**: `content:validate`, `palette:check`, asset dimension tests, browser smoke, production build를 통과한다.
